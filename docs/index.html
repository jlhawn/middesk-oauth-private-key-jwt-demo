Private key JWT clients that rotate their own keys

A Node.js client authenticates with RSA keys instead of a shared secret, holds 10-minute access tokens, and swaps in a new key without an API key.

client_credentials · private_key_jwt (RFC 7523) · RS256 · Node.js + jose

Overview · four ideas

What the demo shows

01 Asymmetric client auth The client signs a JWT with its private RSA key. Middesk stores only the public key.
02 Short-lived tokens access_token_ttl of 600 seconds, so tokens expire after 10 minutes, not an hour.
03 Self-service key rotation The client adds and retires keys by signing the request with a key it already holds.
04 Real calls, real audit trail The token creates a business, and the security event logs show each rotation.

01 · Bootstrap

Register the client with an API key, once

const k1 = await generateSigningKey('k1');

const client = await middesk.createOAuthClient(apiKey, {
  name: 'Key rotation demo',
  redirect_uri: 'https://example.com/oauth/unused',
  allowed_grant_types: ['client_credentials'],
  token_endpoint_auth_method: 'private_key_jwt',
  access_token_ttl: 600,
  jwks: { keys: [k1.publicJwk] },
});
  • generateSigningKey makes a 2048-bit RSA key pair with jose and exports the public half as a JWK with a kid.
  • private_key_jwt clients can only authenticate with signed assertions, so the response has secret: null.
  • access_token_ttl: 600 gives every token a 10-minute lifetime. The maximum is 24 hours.
  • This is the only call that needs the API key. The demo also uses it to delete the client at the end.

01 · Client assertion

A short-lived JWT, signed with the private key

const assertion = await new SignJWT({})
  .setProtectedHeader({
    alg: 'RS256',
    kid: key.kid,
  })
  .setIssuer(clientId)
  .setSubject(clientId)
  .setAudience(audience)
  .setIssuedAt()
  .setExpirationTime('2m')
  .setJti(randomUUID())
  .sign(key.privateKey);
ClaimRule
iss, subThe client_id
audThe endpoint it's sent to, such as https://api.middesk.com/oauth/token
jtiUnique. Middesk accepts each one once.
exp − iatAt most 10 minutes
kid headerPicks the registered public key that verifies it

02 · Rotation request

One form-encoded PUT, signed by a current key

async replaceJwks({ clientId, key, jwks }) {
  const path =
    `/oauth/clients/${clientId}/jwks`;
  const assertion = await clientAssertion({
    clientId,
    key,
    audience: `${this.issuer}${path}`,
  });

  return this.#form(path, {
    jwks: JSON.stringify(jwks),
    ...assertion,
  }, 'PUT');
}
# request

Content-Type: application/x-www-form-urlencoded

&jwks={"keys":[{"kid":"k1",...},{"kid":"k2",...}]}

02 · Guard rails

Rules the endpoint enforces

Its own audience

Assertions must name …/oauth/clients/<id>/jwks. Token assertions don't work here, and these don't work for tokens.

Single use

Every jti is recorded and lifetimes over 10 minutes are refused, so a captured assertion can't be replayed.

Keep the signing key

The new set must still hold the key that signed the request, with the same key material.

Only the key set

Redirect URI, grant types, token lifetime and auth method still need the account's API key.

private_key_jwt only

Secret-based clients are refused, so keys can't be planted before a switch to private_key_jwt.

Audited

Every change writes a change_settings security event with the key IDs before and after.

02 · Design choice

Why rotation doesn't take a bearer token

Rejected

Rotate with an access token

A leaked 10-minute token could add an attacker's key and become a permanent credential.

Chosen

Rotate with a signed assertion

Each change proves possession of a registered private key, in a single-use JWT addressed to this endpoint alone.

Also note ·Client credentials only authenticate on the /oauth endpoints: token, revoke and jwks. Everything under /v1 takes tokens.
